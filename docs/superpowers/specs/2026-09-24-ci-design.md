# Midview — Continuous Integration (Design)

Date: 2026-09-24
Status: Implemented 2026-09-24

## Context

Midview is Windows-only, and most of it had only been tested on Linux: the
Session and Master test projects, the GDI+ tests in Protocol, and the
installer scripts (written for Windows PowerShell 5.1) couldn't run there.
GitHub Actions' Windows runners can run all of it on every change, before
anything reaches the lab.

## Design

- **`.github/workflows/testes.yml`, "Testes (Windows)":** on pushes to
  `master`, on pull requests and by hand. It builds `Midview.sln` (Release)
  and runs every test project. `--blame-hang-timeout 5m` turns a test stuck
  on a socket into a failure with a dump instead of a 30-minute timeout. The
  `.trx` results are kept for 7 days.
- **`.github/workflows/pacote.yml`, "Pacote de instalação":**
  - builds the package with `installer\Gerar-Pacote.ps1` and checks it with
    `installer\tests\Testar-Scripts.ps1`, both under `powershell.exe`, i.e.
    Windows PowerShell 5.1, the one lab machines have;
  - the check parses every script, confirms the BOM, ASCII and CRLF the
    builder adds, and runs the shared functions for real, including the 5.1
    `ConvertFrom-Json` quirk with a one-item list;
  - runs on pushes to `master` that touch `src/` or `installer/`, on pull
    requests that touch `installer/`, and by hand. Run by hand ("Run
    workflow"), it also keeps the package for download for 7 days: a ready
    package for the lab without a local .NET SDK.
- **Minutes:** the repository is private, and on the free plan Windows
  minutes count double. So the package job doesn't run on every pull
  request, and package artifacts are only kept when asked for.

## Out of scope

Signing the executables, publishing releases, and running on anything but
Windows.
